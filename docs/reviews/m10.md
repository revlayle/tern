### 1. Must fix: an `interrupt fn` that is never compiled still makes its callee a part

`Checker.cs:1481` sets `fn.IsPart = true` while the caller's body is checked, whether or not the caller is compiled. Spec 6.3: "a part if it is called, otherwise a handler", and "a module's handler is compiled only when a compiled function names it". An uncompiled module handler calls nothing.

```
// timer.tern
var ticks: u8
interrupt fn tick() { ticks += 1 }
interrupt fn both() {
    tick()
    ticks += 2
}

// main file
import timer
import c64
fn main() { c64.set_irq(addr(timer.tick)) }
```

gives "'timer.tick' is called by another interrupt fn (so it is compiled as a part, ending with rts) and its address is also used to install it". `timer.both` is never named, so `tick` is called by nothing that is compiled and should be an ordinary handler. Mark parts from the call graph of the compiled roots (in or after `OrderRoots`), not in `CheckCall`. The main file's handlers are always compiled, so the case only arises in modules, which is where M11's libraries will offer both kinds. Test: the program above compiles, and `tick` ends with `rti`.

### 2. Must fix: a failed `assert` on a constant derived from a parameter is reported in the module

`CheckAssert` (`Checker.cs:268`) reports at the import only when the condition names the parameter itself (`Mentions`). Spec 4.1: "the error also names the main file's `import` line when a module parameter caused it". A constant computed from a parameter is the usual case for size checks:

```
// sprites.tern
module sprites(COUNT: u8 = 32, FLICKER: bool = false)
const SIZE = COUNT * 4
assert SIZE <= 128, "sprites.COUNT must be 32 or less"
...
// main file
import sprites(COUNT = 40)
```

is reported at `sprites.tern:3:1`, not at the main file's import. Follow names through the module's constants (a `ConstSymbol` could record which parameters its value used), and add this case to `A_failed_assert_names_the_import_line_when_a_parameter_caused_it`.

### 3. Must fix (message): a main-file constant using `sizeof` or `len` is reported as "not declared"

Spec 2.2 allows "the main file's constants that do not depend on imported modules" in a parameter value. `ParameterScope` (`Checker.cs:238`) declares the scratch copy's constants without its structs or data, so these fail and are skipped:

```
import sprites(COUNT = S)
struct Enemy { x: u8, y: u8 }
const S = sizeof(Enemy) * 4
```

gives "'S' is not declared. A parameter value uses literals and the main file's constants that do not depend on imported modules". `S` is declared and depends on no import, so the message is wrong. Either declare and lay out the scratch copy's structs (and `data` lengths) before its constants, which makes the program compile as the spec says, or name the reason ("'S' uses sizeof, which a parameter value cannot use") and ask the spec session to narrow 2.2. The first seems small. Test in `ModuleParameterTests`.

### 4. Suggestion: a handler that leaves through an asm `jmp` gets no `cld`

`CodeGen.cs:342` adds `cld` only for `adc`, `sbc` or `jsr` in the handler. A C64 handler that chains to the KERNAL is a common shape:

```
interrupt fn h() {
    n = 5
    asm { jmp $EA31 }
}
```

compiles to `pha` / `lda #5` / `sta n` / `jmp $EA31` with no `cld`, so the KERNAL's code runs in decimal mode when main is inside `bcd.add`. This follows the letter of 6.3 ("no `adc` or `sbc` in its code or asm blocks, and no `jsr`"), but not its reason. Treating an asm `jmp` to an address outside the function (and `jmp (...)`) like `jsr` costs one byte in such handlers. A question for the spec session, since it changes the 6.3 rule.

### 5. Suggestion: `min8`, `max8`, `clamp8` and the signed ones use `math`'s private work bytes

They are `inline asm fn` so that they cost no `jsr`, but they write `math.w0`-`w2`, shared with `mul8`, `div8` and the rest. A program that calls `math.mul8` from main and `math.min8` from a handler gets the private-variable error ("'math.mul8' (called from main) and 'math.min8' (called from the interrupt handler 'h') both use 'math.w0'"). That is correct (the bytes really are shared), but small inline helpers are the functions a handler would most like to use. Giving them their own private bytes would at least separate them from the multiply and divide routines. Not required by the roadmap.

### 6. Suggestion: library cycle table is partial

The roadmap asks for cycle counts in `docs/status.md`'s library table. Missing: `mem.copy_back`, `text.dec8s`/`dec16s`/`dec8z`/`dec16z`, `math.sin8`/`cos8` and the min/max/clamp helpers (fixed, from the listing), `bcd.less`/`equal`/`digits`, and the 24-bit `wide` routines other than `add24`, `mul24`, `div24`, `dec24`.

### 7. Suggestion: small things

- `assert` inside a function gives "Expected an expression, found 'assert'". Something like "'assert' is a top-level declaration; put it outside the function" would say how to fix it.
- `examples/arcade.tern:94`: "The score changed: show it" sits on code that converts every frame, unconditionally; the header comment says the digits are made only when the score changes. Either test for a change or reword the comment.
