**Correctness probes, all correct:**

- `[u16; 3]` array field through a pointer with a variable index: `=`, `+=` (with carry out of the low byte), `+= $FF01` (wrap past `$FFFF`), reads, and `==`. Y goes `off + i`, then `tya` / `clc` / `adc #len` / `tay` for the high byte; A is saved first or reloaded after in both callers of `NextPointerByte`.
- `i16` field through a pointer: `0 - 1`, `< 0`, `32767 + 1`, sum of two fields.
- Arrays of structs: `u16` field `+=` across `$00FF`→`$0100`, a constant-index `[u16; 2]` array field (`$FFFF + 1`), each byte at `base + k*n + i`.
- `[u16; 4]` array field of a struct variable, in loops with the field as the bound.
- `for ... using X` and `using Y` over arrays of structs: `sta t,x`, `lda t,y`, no extra index loads.
- Local struct variables in nested calls (frames do not overlap); a `ptr S using AX` parameter; a field through a call result (`get().b`, also assigned) and through a cast.
- `q.name[i] = p.name[i]` shares one Y load only when the offsets match; `q.a = p.b` does not.
- Fixed-address struct: fields are volatile, `u16` fields `+= 1` give `inc` / `bne` / `inc`.
- `linear` records with `u16` and array fields, stepped with `sizeof`.
- A struct over 256 bytes: views reach any offset; through a pointer the 0-255 limit gives a clear error.
- `lib/c64`: the VIC-II, SID (voices at `$00`/`$07`/`$0E`, `cutoff` at `$15`, `env3` at `$1C`) and CIA register offsets match the hardware.

## Findings

### 1. Suggestion: calling a field says the struct variable is not declared

`Checker.cs:108` (`NotDeclared`), the same issue as M4 suggestion A, which was not fixed. With structs it is now easy to hit:

```
struct S { a: u8 }
var s: S
fn main() { s.a() }
```

gives `'s' is not declared. To use the module s, add 'import s' at the top of the file`. The same happens through a pointer (`p.a()`). Fix: give the import message only when `Lookup(prefix)` is null; otherwise say e.g. `'s.a' is a field, not a function`.

### 2. Suggestion: arithmetic on a struct gives a confusing type error

`Checker.cs:1186`, reached from `Unify` in `CheckBinary`. `s + 1` with `s: S` gives `Expected S, found a number`. Comparisons already have their own check (`Structs cannot be compared`). Add the same for arithmetic and bit operators, e.g. `A struct is not a number; use one of its fields, e.g. s.a + 1`.

Related: `var x = s` (type inferred from the initializer) gives `A struct cannot have an initial value. Assign its fields` (`Checker.cs:573`). Here `x` was not declared as a struct, so `A struct cannot be used as a value ...` (the `Coerce` message) would fit better.

### 3. Suggestion: a 16-bit operation between fields of the same struct uses a temporary it does not need

`CodeGen.cs:1745` (`ReadsVar`) now compares storage, so every field of a struct counts as the same variable:

```
struct S { a: u16, b: u16, w: u16 }
s.w = s.a + s.b
```

copies `s.b` to a temporary first (4 extra instructions, 14 extra cycles), while the same code with plain variables (`z = x + y`) uses `y` directly. The check is only needed when the bytes overlap. Fix: for views, compare `Storage` and the byte ranges (`AliasOffset` .. `AliasOffset + Size`, and the high table for split arrays). This is safe to leave for M7, but it is a two-line change.
