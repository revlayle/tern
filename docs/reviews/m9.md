### 6. Must fix: code patched from another function is still miscompiled

`selfModifying` looks only at the function being optimized. Asm can name another function (spec 9), and `sta g+1` patches the operand of `g`'s first instruction. `g`'s own code has no write to a label, so its asm `lda #0` is still taken as a known value:

```
var out: u8
fn g() {
    asm { lda #0 }
    out = 0
}
fn main() {
    asm {
        lda #7
        sta g+1
    }
    g()
}
```

Expected `out` = 0; the result is 7 (the generated `lda #0` in `g` is removed). Correct on `main`. Dot labels are local, so a function's entry is the only label another function can patch, but "set a routine's parameter by patching its first instruction" is a common idiom.

Fix, simplest first: make `selfModifying` program-wide (if any asm instruction anywhere writes to a code label, asm instructions forget everything in every function); or record on the `FunctionSymbol` that an asm write names it (as `UsedAddresses` is recorded) and treat that function as self-modifying too. Add the program above as a test.

A check that nothing but the `jmp` lies between the body's last asm instruction and the branch would hold the rule against later optimizer changes.

## Verdict

**Not ready to merge.** Two optimizer changes produce wrong code: the bit 7 fold accepts an indexed load, and asm instructions are now followed closely enough that self-modifying code is miscompiled. Both are small fixes. The rest is good: the variable step and `inline asm fn` match the spec, the sieve loop is the assembly version's loop, and the totals are well below M8's.

## Findings

### 1. Must fix: the bit 7 fold treats `lda a,x` as `lda a`

`Optimizer.FoldShiftTests` (`src/Tern.Compiler/Backend/Optimizer.cs`, the `load1` / `load2` match) checks that A already holds `x`, the operand of the first `lda`, but not the load's addressing mode. The state records `lda a` (that is, `a[0]`) as `VarOperand(a)`; an indexed `lda a,x` has the same operand. When A holds `a[0]` and both arms start with `lda a,x` / `asl a`, both loads are removed and the arms shift `a[0]` instead of `a[i]`:

```
var a: [u8; 4]
var b: [u8; 4]
fn main() {
    a[0] = $80
    a[1] = 1
    a[2] = 2
    a[3] = 3
    for i in 0..4 {
        var t: u8 = a[0]
        if t & $80 != 0 { b[i] = a[i] << 1 } else { b[i] = a[i] << 1 }
    }
}
```

Expected `b` = 0, 2, 4, 6; the result is 0, 0, 0, 0. Generated loop: `lda a` / `sta main.t` / `asl a` / `bcc else` / `sta b,x` ... (no load of `a,x`).

Fix: require `Trackable(load1)` (absolute or zero-page mode), as `RemoveRedundant` does for loads. Add this program as an `OptimizerTests` case.

### 2. Must fix: self-modifying assembly is miscompiled

Since `3dbbce7`, asm instructions are followed like generated ones, so an asm `lda #0` makes the optimizer believe A holds 0. If the block patched that immediate, it does not, and a later generated `lda #0` is removed:

```
var out: u8
fn main() {
    var v: u8 = 7
    asm {
        lda v
        sta .smc+1
    .smc:
        lda #0
    }
    out = 0
}
```

Expected `out` = 0; the result is 7 (`main`: `sta main.smc0+1` / `lda #$00` (asm) / `sta out`; the generated `lda #0` is gone). On `main` this program is correct, since any asm instruction forgot everything. Patching an operand is a common 6502 idiom (also an address: `sta .ld+1` / `.ld: lda $FFFF` would be taken as a load of a known variable).

A write whose operand is a code label (a `LabelOperand`, not a variable) is the sign. Possible fixes, simplest first: in a function that has such a write, treat every asm instruction as forgetting everything (the old behavior); or do not remember the value of any asm load whose instruction lies after a label named by such a write. Either way, add the program above as a test in `OptimizerTests`. Spec 9 says the compiler "computes which registers, flags and variables a block reads and writes"; it may be worth a sentence there or in `docs/decisions.md` that self-modifying code is supported (or not), so the rule is written down.

### 3. Suggestion: a negative folded address costs a cycle per access in zero page

`FoldIndexOffset` folds `a[i - c]` also when `a` is in zero page below `c`. `a` at `$02`, `a[i - 5]` gives `lda $FFFD,x`: correct (absolute indexing wraps at 64K), but absolute instead of zero page and a page crossing on every access (`4+` becomes 5 cycles), and on a store a dummy read at `$FFxx`. Not wrong, and cheaper than the `sec` / `sbc` it replaces. Folding only when `address - c >= 0` would keep zero-page arrays in zero-page mode; the address is not known at code generation time, so this may be left as is. Mention it in the status notes if kept.

### 4. Suggestion: status does not mention "X (or Y) reused across array accesses with the same index"

The roadmap lists it as an optimizer item. It already holds (the M7 redundant-load pass removes the second `ldx i`: `b[i] = a[i] + c[i]` loads X once), but `docs/status.md` lists neither the item nor that it needed no change. Add one line, ideally with a listing test if there is none.

### 5. Suggestion: the label-position dictionary is built five times

`ThreadJumps`, `RemoveUnreachable`, `Analyse`, `RemoveRedundant` and `FoldShiftTests` each build the same `Label -> index` map with the same three lines. A `Positions(code)` helper would shorten each.

## Checked and fine

- Variable step: evaluated once (in place for an unchanged local, else a temporary), entry check for variable bounds, `..=255` ends on `adc` / `bcc` with no compare (also for constant steps), `5..5 step n` emits nothing. Checked with variable start and end (empty, one value, several), and with an asm block writing the step variable (`AssignsVar` sees the asm write, so a temporary is used). The `for m in (n << 1)..=255 step n` listing matches the spec 11 shape (`txa` / `clc` / `adc main.n` / `tax` / `bcc`, X instead of Y without `using`).
- Error messages for signed, 16-bit, non-`u8`-counter and counting-down steps, memory parameters, `rts`/`rti` in an `inline asm fn`; all have tests. `jsr f` and `addr(f)` on an `inline asm fn` give the existing `inline` errors.
- `inline asm fn`: dot labels are renamed per copy (two copies in one function work); an interrupt handler saves the registers an inlined body changes; a loop counter is not kept in X when the body calls an `inline asm fn` that changes X; an empty body with `-> bool using zero` stored into `b[i]` keeps the flag (the `ldx i` comes after the flag is turned into 0/1).
- `Same` markers: a stale marker left in one register cannot make a transfer look redundant, since `RemoveRedundant` needs the marker in both sets, and only a transfer between those two registers adds it.
- `NzLiveAfter`: follows `jmp` and both branch directions, gives up on indirect jumps, tables and asm `rts`.
- `ThreadJumps` never changes asm instructions, and the assembler still turns out-of-range generated branches into a branch over a `jmp`.
- Benchmark commits give the old and new totals.
