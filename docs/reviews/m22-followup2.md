### Findings

**1. Suggestion: the emulator tests for the new empty check cover only `using X` with a plain start.** `LoopDirectionTests.An_unsigned_down_count_to_0_tests_only_its_start` runs `n..0 step -1 using X`. The other three paths through the new branch are in no new test:

- a counter in memory (`lda c` / `beq`)
- a counter in Y (`cpy #$00`)
- a start that leaves the flags changed (`cpx #$00` after `(n + 1)` / `tax`), and a step other than -1 (`n..0 step -2`)

I ran each of them by hand for n = 0, 1, 5 and 255 and they are correct. Adding them as rows (n = 0 and 5 at least, plus `(n + 1)` with n = 255, which wraps to an empty loop) would protect the `!flagsHoldStart` paths.

**2. Suggestion: a variable held in the other index register puts a compare back in.** `HoldInRegister` runs after `SetCounter`. When it loads a held variable, the flags from `ldy n` are lost, so `for i in n..0 step -1 using Y { cnt += 1 }` compiles to `ldy n` / `ldx cnt` / `cpy #$00` / `beq done`, 2 bytes and 2 cycles more than spec 11's shape. This happens once per loop, not per pass, and the old code had the same order. Emitting the empty check before the held register's load (when the check needs only the counter's flags) would save the `cpy`. The signed case (`SignedEmptyCheck` with `flagsHoldStart`) has the same order, so a fix there would help both. This is not a must-fix: spec 11's row has a plain body, and the branch matches it.
