# 6. Commodore 64

[Guide index](README.md) · previous: [5. Standard library](05-library.md) · next: [7. Atari 8-bit](07-atari.md)

## 6.1 The target

`--target c64` writes a `.prg` that loads at `$0801`, with a BASIC line `10 SYS 2061` so that `RUN` starts it. The startup code zeroes globals, copies initial values and calls `main`; when `main` returns, the program stops in an endless loop, and interrupt handlers keep running. It does not return to BASIC, whose zero page the program has used ([10.15](10-behavior.md#1015-when-main-returns)).

- Memory: code from `$0801`, variables up to `$9FFF`; zero page `$02-$8F` and `$FB-$FE`. The KERNAL and I/O stay mapped in.
- I/O at `$D000-$DFFF` and the KERNAL's own variables (keyboard buffer, clock) are volatile with no keyword.
- Strings are PETSCII; `screen"..."` gives screen codes.
- Run it in VICE: `x64sc -autostart game.prg`. The `.vs` file loads the program's labels in VICE's monitor (`ll "game.vs"`).

## 6.2 Text on the screen

```
import c64
import text

data title = screen"HELLO, TERN"

fn main() {
    c64.vic.border = c64.BLACK
    c64.vic.background = c64.BLUE
    text.put(c64.SCREEN + 12 * 40 + 14, addr(title), len(title))
    while true { }
}
```

82 bytes, including the BASIC line and startup code. `c64.print(addr(s), len(s))` prints PETSCII through the KERNAL instead, at the cursor.

## 6.3 The `c64` module

| Name | Purpose |
|---|---|
| `SCREEN`, `COLOR`, `BLACK` ... `LIGHT_GREY` | Screen and color memory, the 16 colors |
| `chrout`, `print`, `getin`, `cursor`, `get_cursor` | KERNAL text output, keyboard and cursor |
| `load(name, n, device)` | Load a file to its own address, e.g. an overlay ([3.5](03-memory.md#35-overlays)) |
| `vic`, `sid`, `cia1`, `cia2` | The chips' registers as structs: `c64.vic.border = c64.BLACK` is `lda #0` / `sta $D020` |
| `sprite_xy` | The sprite positions as an array of 16 bytes (x of sprite n at 2n, y at 2n + 1) |
| `kernal_off`, `set_irq`, `set_nmi`, `set_kernal_irq`, `cia_irqs_off`, `interrupts_on`, `interrupts_off` | Interrupt setup ([6.4](#64-interrupts)) |

A list of enemies, with the border color written through `c64.vic`:

```
import c64

struct Enemy { x: u8, y: u8, hp: u8 }

const COUNT = 8
var enemies: [Enemy; COUNT]
var alive: u8

fn spawn() {
    for i in 0..COUNT {
        enemies[i].x = (i << 4) + 24
        enemies[i].y = 50
        enemies[i].hp = 3
    }
}

fn advance() {
    alive = 0
    for i in 0..COUNT {
        if enemies[i].hp == 0 { continue }
        enemies[i].y += 1
        alive += 1
    }
}

fn color_for(hp: u8) -> u8 {
    match hp {
        0 => return c64.BLACK
        1 => return c64.RED
        2, 3 => return c64.YELLOW
        _ => return c64.WHITE
    }
}

fn main() {
    spawn()
    advance()
    c64.vic.border = color_for(enemies[0].hp)
}
```

`spawn` and `advance` never run at the same time, so their loop counters share memory.

## 6.4 Interrupts

```
import c64

var band: u8

interrupt fn raster() {
    c64.vic.irq_status = 1               // acknowledge
    band += 1
    c64.vic.border = band & 7
    c64.vic.raster = 50 + ((band & 7) << 4)
}

fn main() {
    c64.kernal_off()                     // KERNAL out, interrupts held off
    c64.set_irq(addr(raster))
    c64.vic.control1 = c64.vic.control1 & $7F
    c64.vic.raster = 50
    c64.vic.irq_enable = 1
    c64.interrupts_on()
    while true { }
}
```

`band` is used by the handler only, so it is ordinary memory. If main also read it, it would become volatile automatically. See `examples/c64/raster.tern` for a fuller version.

`kernal_off()` switches the KERNAL and BASIC ROMs out (I/O stays), turns off the CIA interrupts and ignores RESTORE; KERNAL routines cannot be called afterwards. With the KERNAL left in (needed by the `io` library), `set_kernal_irq(addr(handler))` installs the same kind of handler through `$0314`; the KERNAL's keyboard scan then stops. For a raster interrupt there, call `cia_irqs_off()` first, which turns off the CIA timer interrupts and clears any that are pending (`examples/c64/kernal_irq.tern`).

## 6.5 Files: `io`

`io` is device I/O through the KERNAL, so it needs the KERNAL banked in: `io.load` and `io.save` move whole files (`save` takes the first and last address, the last included), `io.open`, `io.read`, `io.write` and `io.close` work on sequential files, and `command_open`, `command`, `drive_status` and `command_once` talk to the drive's command channel. Results that are `bool` are true on failure. `examples/c64/highscore.tern` saves a high-score file and loads it back.

## 6.6 Sprites and scrolling

- **`sprites`** is a sprite multiplexer: `import sprites(COUNT = 24)` for 8 to 64 sprites. The program writes the sprite table (`sprites.xpos`, `ypos`, `frame`, `color`, `flags`), calls `sprites.update()` once a frame and `sprites.wait_frame()`; `sprites.start()` installs its own raster interrupt, or `sprites.raster()` is a part of your own handler. A sprite must start at least 30 lines below the sprite 8 places before it in y order, or it is skipped that frame (`FLICKER = true` makes skipped sprites take turns).
- **`scroll`** scrolls a character map smoothly in eight directions on two screens: `scroll.set_map(addr(map), width)`, `scroll.draw(x, y)`, then `scroll.move(dx, dy)` each frame. With `COLORS = true` it also redraws color RAM from a color map.

`examples/c64/scroller.tern` scrolls a map under 24 multiplexed sprites. The limits and costs are in spec 10.1.

## 6.7 `tern run` on the C64

The built-in emulator has no VIC-II, SID or CIA, and no KERNAL: `CHROUT`, `GETIN` and `PLOT` have stand-ins, and `c64.load` works for the program's own overlays when the file name is the module's name in capitals (`"LEVEL1"` loads `level1.prg`). Any other name fails as a missing file does, and other KERNAL calls stop the run; check such a program in VICE. `--screen` shows the text screen at `$0400`, and `--irq <n>` raises an IRQ every `n` cycles.
